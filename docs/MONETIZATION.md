# 원두레이더 — 첫 유료 파일럿

2026-10-02 기준 제안 및 구현 계약. 가격·고객 수요는 가설이다. 기능 구현, 운영 설정 존재, 실제 결제·서비스 제공은 서로 다른 증거다.

## 상품과 고객

여러 로스터리의 관심 원두를 반복 확인하는 홈카페 사용자의 방문 수고를 줄인다. 특히 즐겨찾기 4개 이상을 계속 지켜보는 사용자가 첫 고객 가설이다.

| 항목 | 무료 | 프리미엄 파일럿 |
| --- | --- | --- |
| 확인 대상 | 먼저 등록한 즐겨찾기 3개 | 전체 즐겨찾기 |
| 확인 주기 | 일일 수집 기준 | 동일 |
| 안내 | 판매페이지에 다시 나타난 상품, 가격 인하 | 동일 |
| 가격 | 0원 | 2,900원 / 30일 |
| 결제 | 없음 | 운영자 입금 확인 후 수동 활성화, 자동 결제 없음 |

가격 인하는 두 플랜 모두 제공한다. 가격 상승은 개인 알림 대상이 아니다. 일일 수집은 즉시 재입고 탐지나 구매 성공을 의미하지 않는다. 상품이 목록에 다시 나타나는 것을 재입고의 대리 신호로 사용하므로 실제 재고와 다를 수 있다. 변화가 없으면 메시지가 없을 수 있고 수집 실패 시 확인이 늦어진다. 최종 가격·중량/옵션·재고는 판매처가 기준이다.

## 이번에 닫는 흐름

`공개 /premium 안내 → 로그인/즐겨찾기/텔레그램 연결 → 유료 접수 준비 확인 → 신청 → 운영자 안내 → 수동 입금 확인 → 30일 활성화 → 만료/갱신`

- 최초 기간은 활성화 시점부터 정확히 30 × 24시간이다. 조기 갱신은 유효한 기존 만료일에 30일을 더한다.
- `premium_config/pilot.salesEnabled === true`일 때만 유료 신청과 신규 입금 활성화가 가능하다. 문서 없음·읽기 실패는 판매 준비 미확인이다. 무료 기능은 유지한다.
- 이번 작업은 해당 설정 문서를 생성하거나 바꾸지 않는다. 설정 기능을 구현했다는 사실은 현재 운영 판매 상태를 변경했다는 뜻이 아니다.
- 같은 거래 식별값은 사용자·신청에 한 번만 반영된다. 신청 처리, 권한, `premium_payments` 운영자 확인 기록을 하나의 Firestore transaction으로 저장한다.
- `premium_payments.verification = operator_confirmed`는 운영자 확인 기록이다. 은행 거래를 자동으로 조회·검증한 증거가 아니다.
- 기존 만료 없는 수동 권한은 유지하며 결제로 세지 않는다. 운영자가 기간을 확인하기 전에는 새 유료 기간으로 덮어쓰지 않는다.
- 발송은 `uid × eventId` 원장으로 반복 실행과 동시 실행을 통제한다. 전송 성공은 Telegram 성공 응답과 message ID로 확인한다. 결과 불명은 자동 재발송하지 않는다. 네트워크와 원장 사이 장애까지 포함한 절대 exactly-once는 보장하지 않는다.

## 판매 시작 전 운영 확인

구체적인 수취 계좌, 판매자 정보, 문의·취소·환불 처리 조건과 응답 가능 시간이 정해져야 한다. 미확인 정보나 24시간 처리 보장은 화면에 만들어 넣지 않는다. 수집 품질과 실제 테스트 계정 DM 수신도 확인해야 한다.

특히 현재 이벤트 생성은 후속 crawl validation 전에 기록된다. 일부 로스터리 수집 실패, 목록 파싱 변화, 다른 중량·옵션 가격을 실제 상품 변화로 오해할 위험이 있다. 이번 범위는 수집 파이프라인을 바꾸지 않는다. 대상 로스터리의 최근 정상 수집과 실제 상품 페이지 대조가 끝나기 전에는 판매 준비 완료로 판단하지 않는다.

[2026-10-02 정규 run](https://github.com/Youngkwon-Lee/coffee/actions/runs/36946159733)에서 main 크롤·검증·Firestore 반영·채널 발행이 성공했다. 개인 DM은 대상이 없어 발송되지 않았으므로 실제 DM 수신 증거가 아니다. 허가된 테스트 계정의 연결·개인 DM 성공과 이후 일일 일정 관측은 판매 시작 전 필수다.

운영 baseline과 독립 검증은 `docs/REVENUE_PILOT_PROGRESS.md`, 구체적인 운영 절차는 `docs/PREMIUM_PILOT_RUNBOOK.md`에 기록한다. 과거 문서의 구독 의향·경쟁 부재·예상 매출 표현은 검증된 수요나 현재 시장 사실로 사용하지 않는다.

## 성공 기준과 다음 투자

1. 은행 거래와 대조하여 입금이 확인된 독립 고객 5명, 사용자별 약속 기간의 서비스 제공을 확인한다.
2. 첫 기간 종료 후 실제 재결제를 별도로 확인한다.
3. 신청 수, Telegram 연결 수, `plan: premium`, 이용권 부여 시각은 매출이나 활성 고객 지표가 아니다. 취소·환불은 별도 대조한다.

5명은 첫 매출 검증 기준이며 사업성이나 반복 매출을 입증하지 않는다. 결제 자동화·로스터리 제휴·B2B 상품은 실제 재결제와 운영 비용을 본 뒤 별도 범위로 결정한다. 이번에는 PG, 구독 자동 갱신, 마케팅 발송, 새 스케줄을 추가하지 않는다.
