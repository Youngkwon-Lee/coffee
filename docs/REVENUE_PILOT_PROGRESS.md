## 결정

- 판매 설정이 없거나 읽기에 실패하면 기본적으로 준비 중이다. 판매를 열기 전 운영 조건과 실제 전달 경로를 확인한다.
- 무료는 관심 원두 최대 3개, 유료는 전체 관심 원두의 관측된 목록 복귀·가격 인하 알림이다. 실시간 재고나 구매 성공을 약속하지 않는다.
- 입금 참조를 한 번만 처리하고 남은 이용 기간을 보존한다. 운영자 확인 기록은 은행이 검증한 거래 데이터와 구분한다.
- 알림 응답이 불명확한 경우 자동 재발송하지 않고 확인 대상으로 남긴다. 외부 API의 정확히 한 번 전달은 보장하지 않는다.
- 운영 Firestore 쓰기, 고객 메시지·과금, 배포, 규칙 배포, 판매 스위치 변경은 이번 로컬 구현 검증에 포함하지 않는다.

## 증명과 종료 조건

완료 기준은 상태·입금 중복 처리·권한 규칙·발송 결과 테스트, 로컬 빌드 및 변경 파일 정적 검사, 좁고 넓은 화면의 렌더 검증, 운영 절차 문서다. 기존 저장소 오류는 새 오류와 구분한다. 외부 인증·서비스 실패는 새 증거 없이 반복하지 않는다.

신청 수나 권한 플래그를 매출로 보고하지 않는다. 판매를 열고 고객을 유치하는 단계는 별도 실행 결과로 남긴다.

## 후속 출시 준비의 안전성 수정

기존 E2E 도구는 실제 즐겨찾기를 덮어쓴 뒤 삭제하고 고정 이벤트를 전체 사용자 발송기에 넘겼다. 이를 실행별 UUID, 단일 사용자·이벤트 범위, 소유권 확인 cleanup으로 바꿨다. 현재 플랜 한도는 그대로 적용하고 일반 일일 발송에서는 테스트 이벤트를 제외한다. 무료 사용자의 실제 즐겨찾기와 결제 권한을 변경하지 않는다.

추가 오프라인 검증: 실행소유 fixture 8건, Python 발송 25건(기존 17 + 범위 제한 8), 만료 18건 통과. 수동 workflow의 UUID/scoped 호출과 기존 runner·일정 불변을 확인했다.
실제 Admin SDK를 Firestore demo emulator에 연결한 추가 검증도 통과했다. 기존 즐겨찾기의 내용·시각 불변, 가상 fixture의 원자적 생성과 정확한 삭제를 확인했으며 운영 DB에는 쓰지 않았다.
